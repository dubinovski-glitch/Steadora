React Application

The frontend is a single-page app in web/src/ built with React 18 + TypeScript, Vite, Tailwind CSS, and Zustand for state management. It talks to the API via a thin typed Fetch wrapper. Theming and density preferences are applied via data-theme / data-density attributes on the root element.

App.tsx — Shell

The application shell. It:

  • Renders the Sidebar and Topbar layout components
  • Reads view from useAppStore and conditionally renders the matching feature view
  • Manages the openIncidentId state that shows/hides IncidentDetailView
  • Shows the NewIncidentModal when showNewIncident is true
  • Provides addToast from useToast() down to all feature views
  • Activates useKeyboard() for global keyboard shortcuts
// View routing (simplified)
{view === 'dashboard'  && <DashboardView  addToast={addToast} />}
{view === 'incidents'  && <IncidentsView  addToast={addToast} />}
{view === 'problems'   && <ProblemsView   addToast={addToast} />}
{view === 'changes'    && <ChangesView    addToast={addToast} />}
{view === 'knowledge'  && <KnowledgeView  addToast={addToast} />}
{view === 'sla'        && <SlaView        addToast={addToast} />}
{view === 'admin'      && <AdminView      addToast={addToast} />}
{openIncidentId && <IncidentDetailView id={openIncidentId} ... />}

api/ — API Client Layer

A thin typed wrapper over the browser's native Fetch API. All calls are relative to /api (proxied by Vite in development to http://localhost:5000).

client.ts — Base client

const api = {
  get:    <T>(path: string)               => request<T>(path),
  post:   <T>(path: string, body: unknown) => request<T>(path, { method: 'POST', ... }),
  put:    <T>(path: string, body: unknown) => request<T>(path, { method: 'PUT',  ... }),
  patch:  <T>(path: string, body: unknown) => request<T>(path, { method: 'PATCH', ... }),
  delete: <T>(path: string)               => request<T>(path, { method: 'DELETE' }),
}

The request<T> helper sets Content-Type: application/json, throws an Error for non-2xx responses, and returns undefined (typed as T) for 204 No Content responses.

hooks/ — Custom Hooks

useToast

Manages a list of transient toast notifications. Each toast auto-dismisses after 2.4 seconds. Returns { toasts, addToast, removeToast }. Used in App.tsx; addToast is passed down as a prop to all feature views so they can show success/error messages.

useKeyboard

Registers a global keydown listener on mount and removes it on unmount. Provides the following shortcuts:

layout/Topbar.tsx

Top header bar. Shows system status indicator, notifications bell (uses unreadCount), user avatar, and a settings menu with theme and density toggles.

primitives/Badge.tsx

Color-coded badge for priority and status codes. Two helper functions exported alongside the component:

  • priorityVariant(code: PriorityCode) — maps critical|high|medium|low to variant names (critical|high|medium|low)
  • statusVariant(code: StatusCode) — maps status codes to default|info|pending|success|default

Variants: critical (red), high (orange), medium (yellow), low (blue), success (green), pending (gray), info (blue), default (neutral).

primitives/Avatar.tsx

Circular avatar displaying user initials on a coloured background. Props: initials, color (hex), size (sm/md/lg).

primitives/SlaBar.tsx

Horizontal progress bar showing SLA elapsed percentage. Colour shifts from green → yellow (50%) → orange (75%) → red (100%+ = breached). Also renders a human-readable "Xh Ym remaining" label.

primitives/Toast.tsx

Toast notification stack. Renders toasts from useToast in a fixed bottom-right stack. Each toast slides in and auto-fades.

features/ — Feature Views

DashboardView

Homepage. Fetches from DashboardController. Displays:

  • 4 KPI cards: open incidents, SLA at risk, changes this week, avg resolution
  • Incidents needing attention table (SLA at-risk queue)
  • Service health grid with coloured status dots
  • SLA summary metrics (met %, breach count)

IncidentsView

Full incident queue with:

  • Tab filter bar: All / Assigned to me / Unassigned / SLA risk / Resolved
  • Free-text search box
  • Bulk selection checkbox + Bulk Close button
  • Sortable incident list rows with priority badge, status, assignee avatar, SLA bar
  • Click row → opens IncidentDetailView
  • "+" New Incident button → NewIncidentModal

IncidentDetailView

Slide-over panel (or full-page) showing a single incident's complete data. Sections:

  • Header: number, title, priority badge, status
  • Metadata sidebar: reporter, assignee (reassignable), group, service, category, CI
  • SLA bar (full size)
  • Description / steps to reproduce
  • Linked problem chip
  • Comments tab: thread of public + internal notes
  • Activity tab: full ActivityEvent timeline
  • Watchers section

NewIncidentModal

Modal form triggered by the "+" button or c shortcut. Fields: title, description, priority (dropdown), service (dropdown), category (dropdown), reporter. On submit calls incidentApi.create() and shows a success toast.

ProblemsView

Problem list with search, state filter (open/resolved), and click-to-detail. Detail view shows root cause, workaround, linked incident count, affected services.

ChangesView

Change management list. State tabs: Draft / Under Review / Approved / In Progress / Completed. Reviewer vote interface shows per-user vote chips with approve/reject/abstain actions.

KnowledgeView

KB article search with category sidebar. Article list shows title, snippet, tag chips, view count, and helpful %. Clicking an article shows the full body and a vote widget.

SlaView

SLA & Reporting dashboard. Four panels:

  1. Overall stats (open, at-risk, met %, breach count)
  2. By-priority breakdown table
  3. Team load table
  4. Daily volume trend (bar chart via CSS or an inline chart library)

AdminView

UsersTab

Table of all users with role badge and active/inactive status. Invite modal creates a new user; edit modal updates role, group, and active status.

TeamsTab

Card grid of groups with member counts. Create/edit modal for name and description.

CategoriesTab

Tree view: expandable category rows revealing subcategory items. Each category shows ticket count badge. Inline delete button (protected by conflict check on the API).

RolesTab

Role cards + static permission matrix table (7 capability areas × 4 roles). Edit modal lets admins update role display name and description.

ServicesTab

Table with health dot indicator, SLA tier badge, owning group, open incident count. Create/edit modal includes health code and SLA tier dropdowns.

PriorityMatrixTab

3×3 grid (Impact rows × Urgency columns) where each cell has a <select> for the resulting priority. Save button POSTs all 9 cells via adminApi.savePriorityMatrix.

SlaPoliciesTab

Two-column layout: tier list on the left, detail panel on the right showing per-priority response/resolution minute fields. Save writes to /api/admin/sla-tiers/{id}/targets.

BusinessHoursTab

Weekly schedule table (Mon–Sun) with start/end time inputs. Holiday list below with date chips and a delete button per holiday, plus an add holiday form.

WorkflowTab

Read-only incident state flow diagram showing the five statuses (New → In Progress → Pending → Resolved → Closed) with transition arrows. Rendered as CSS/SVG boxes.

AutomationsTab

List of automation rules with enable/disable toggle. CRUD modal for name, when-description, and then-description text fields. Run count badge shows executions in the last 30 days.

Repositories

All data-access code lives in ApertureITSM.Infrastructure/Repositories/. Each repository implements one Core interface, uses Dapper for SQL execution, and writes to log4net (all routing to logs/Infrastructure.log).

Common patterns
  • All methods wrap their SQL in try/catch; exceptions are logged with log.Error(..., ex) then re-thrown.
  • Connection is obtained per-method via IDbConnectionFactory.Create() (SqlConnection, disposed with using).
  • Timestamps stored as UTC; returned as ISO-8601 strings via CONVERT(VARCHAR, ..., 120).
  • Soft-delete pattern: DeletedAt IS NULL added to every WHERE clause that should exclude deleted rows.
  • Slug generation: name.ToLowerInvariant().Replace(' ', '-') with regex stripping non-alphanum/dash chars.

DbConnectionFactory · Database/DbConnectionFactory.cs

The only place in the codebase that knows about SQL Server. Implements IDbConnectionFactory which exposes one method: Create() → SqlConnection. The connection string is injected via IConfiguration.GetConnectionString("Default").

public interface IDbConnectionFactory
{
    SqlConnection Create();
}

public class SqlConnectionFactory(IConfiguration config) : IDbConnectionFactory
{
    public SqlConnection Create() =>
        new(config.GetConnectionString("Default"));
}

Registered as Singleton in Program.cs. The returned connection is always opened lazily by Dapper's QueryAsync / ExecuteAsync — you never call Open() manually.

IncidentRepository

Implements IIncidentRepository. The most complex repository — handles filtering, pagination, SLA data, and multi-table joins.

GetPagedAsync

Builds a dynamic SQL query based on the IncidentFilter passed in. Joins:

  • itil.Incident → lookup.Priority, lookup.IncidentStatus
  • → lookup.Impact, lookup.Urgency, lookup.Category
  • → core.Service, core.ConfigurationItem
  • → core.User (reporter, assignee), core.Group
  • → itil.Problem (for parent problem number)
  • Subquery counts for comments and linked tickets

Filter predicates appended conditionally: StatusId IN (...), PriorityId = @p, AssigneeUserId = @a, SlaPercent >= 75 (SLA at-risk), free-text LIKE '%@q%' on title + description.

Pagination via OFFSET @skip ROWS FETCH NEXT @take ROWS ONLY.

CreateAsync

Looks up PriorityId, StatusId (= "new"), CategoryId, ServiceId, CiId, and ReporterUserId by their codes/external IDs, then inserts into itil.Incident. Returns SCOPE_IDENTITY(). Also inserts the initial audit.ActivityEvent row for the "created" event.

UpdateStatusAsync / UpdateAssigneeAsync / UpdatePriorityAsync

Each does an UPDATE itil.Incident SET ... WHERE IncidentId = @id followed by an INSERT INTO audit.ActivityEvent for the audit trail. The two operations run in sequence on the same connection (not a transaction — if the activity insert fails the status is still saved; acceptable trade-off for simplicity).

SoftDeleteAsync

Sets DeletedAt = SYSUTCDATETIME(). All GetPaged queries filter on DeletedAt IS NULL.

ProblemRepository

Implements IProblemRepository.

Tables touched

itil.Problem, lookup.Priority, lookup.ProblemState, core.User (assignee), core.Group, itil.Incident (for LinkedIncidentCount), core.Service (for affected service slugs), audit.ActivityEvent.

Key notes

  • GetAllAsync runs one query for problem rows, then a separate query for linked incident counts grouped by ProblemId, then maps in C#.
  • GetByIdAsync enriches the returned object by querying itil.IncidentService for service slugs (services linked through linked incidents).
  • State transitions write an audit.ActivityEvent with Kind = 'state_change'.

ChangeRepository

Implements IChangeRepository.

Tables touched

itil.Change, lookup.ChangeType, lookup.Risk, lookup.ChangeState, core.User (owner, approver), core.Group, itil.ChangeReviewer, lookup.ApprovalVote, core.Service, audit.ActivityEvent.

Key notes

  • GetAllAsync queries a flat result set then calls a private EnrichAsync helper that batch-loads all reviewer rows in one query and maps them to the correct Change by ChangeId.
  • VoteAsync does a MERGE into itil.ChangeReviewer (one row per change+user) so re-voting updates the existing row.
  • Affected service slugs are loaded separately by querying itil.ChangeService (join table).

KbRepository

Implements IKbRepository.

Tables touched

kb.Article, kb.Category, core.User (author), kb.ArticleTag, kb.Tag.

Key notes

  • SearchAsync uses LIKE '%@q%' on Title and Snippet. For production consider upgrading to SQL Server Full-Text Search (CONTAINS).
  • GetByIdAsync loads the full body then calls EnrichTagsAsync which queries kb.ArticleTag JOIN kb.Tag and populates article.Tags.
  • IncrementViewsAsync runs a single UPDATE kb.Article SET Views = Views + 1 — atomic at row level.

ActivityRepository

Implements IActivityRepository.

Tables touched

audit.ActivityEvent, audit.Comment, audit.Watcher, audit.Notification, core.User, stored procedure itil.usp_AddComment.

Key notes

  • parentType is a discriminator string ('incident'|'problem'|'change') stored directly in the ParentType column — no join table needed.
  • AddCommentAsync calls the itil.usp_AddComment stored procedure which atomically inserts the comment, writes an ActivityEvent, and fans out Notification rows to all watchers.
  • Notifications are soft-read: MarkNotificationsReadAsync sets IsRead = 1 for all rows where UserId = @userId AND IsRead = 0.

UserRepository

Implements IUserRepository. Read-only. Write operations (create/update users, groups) are handled by AdminRepository.

Tables touched

core.User, lookup.Role, core.Group, core.Service, lookup.ServiceHealth, core.ConfigurationItem.

GetByExternalIdAsync

Used at authentication time to resolve a claims-based identity into the app's internal UserId. Returns null if no match (user not yet provisioned).

LookupRepository

Implements ILookupRepository. All methods are simple SELECT ... FROM lookup.X ORDER BY SortOrder queries. No writes — lookup data is managed via seed scripts.

Results are cached by the frontend on first load and served from Zustand state, minimising repetitive calls.

SlaRepository

Implements ISlaRepository.

EvaluateBreachesAsync

Executes the stored procedure reporting.usp_EvaluateSlaBreaches. This procedure:

  1. Creates temp tables #breached and #warned
  2. Updates SlaBreachedAt on incidents that have exceeded their target
  3. Updates SlaWarnedAt on incidents >75% through their target
  4. Recalculates SlaPercent on all open incidents

Called by SlaBackgroundService every 60 seconds.

GetStatsAsync

Calls reporting.usp_DashboardKpis @days which returns a single-row result mapped to SlaStats.

GetTeamLoadAsync

Runs an aggregation query grouping itil.Incident by core.Group, counting open incidents, SLA met, and breached counts per team.

GetDailyVolumeAsync

Groups itil.Incident by CAST(OpenedAt AS DATE) for the last N days, counting total opened and those resolved on the same day.

AdminRepository

Implements IAdminRepository. The largest repository — handles all administrative CRUD. All write operations log at INFO level with entity name/ID for audit trail purposes.

Tables touched

core.User, core.Group, lookup.Category, lookup.SubCategory, lookup.Role, core.Service, lookup.ServiceHealth, admin.SlaTier, admin.SlaTierTarget, lookup.PriorityMatrix, admin.BusinessCalendar, admin.BusinessDay, admin.BusinessHoliday, admin.Automation.

Key patterns

  • BuildInitials — private helper that extracts first+last initial from a display name for avatar generation.
  • GenerateSlug — static helper using fully-qualified System.Text.RegularExpressions.Regex.Replace (avoids namespace collision with ApertureITSM.Core.Models.Group).
  • SaveSlaTierTargetsAsync / SavePriorityMatrixAsync — use SQL MERGE (upsert) so the same method handles both insert and update of matrix/target rows.
  • DeleteCategoryAsync — queries open incident count first; throws InvalidOperationException if > 0 (controller returns HTTP 409 Conflict).
  • GetCategoriesAsync — queries flat category rows with a COUNT JOIN on itil.Incident for TicketCount, then queries subcategories in a second round-trip and assembles the tree in C#.
  • GetSlaTiersAsync — queries tier rows, then target rows in a second query, groups targets to tiers in C# to avoid Cartesian product.
  • GetBusinessCalendarsAsync — three separate queries (calendars, days, holidays) assembled in C#.

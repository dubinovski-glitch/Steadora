Aperture ITSM

A full-stack IT Service Management platform built on .NET 8 / ASP.NET Core (backend) and React 18 / TypeScript (frontend), following clean-architecture principles with ITIL-aligned modules for Incidents, Problems, Changes, and SLA management.

Layer Architecture

The solution is split into five discrete backend layers plus the React SPA, each with a single responsibility and no downward dependencies (each layer depends only on the layer below it).

Dependency Injection Wiring

All registrations happen in ApertureITSM.Api/Program.cs. Each feature can be toggled on or off via the Features section of appsettings.json:

// appsettings.json
"Features": {
  "Incidents": true,
  "Problems":  true,
  "Changes":   true,
  "Notifications": true,
  "Sla":       true
}

When a feature is disabled, a no-op implementation is registered so dependent code never receives a null service reference.

Typical Request Flow

Example: A user opens an incident and the UI fetches the detail.

Browser GET /api/incidents/42
  → IncidentsController.GetDetail(42)
      → IIncidentService.GetDetailAsync(42)
          → IIncidentRepository.GetByIdAsync(42)
              → SQL Server: SELECT from itil.Incident + joins
          ← returns Incident model
      ← returns IncidentDetail DTO
  ← JSON response to browser

Real-Time Notifications

The NotificationHub (SignalR, at /hubs/notifications) pushes events to connected clients when incidents are updated, SLA breaches are detected, or comments are posted. The frontend connects via the browser's native WebSocket support (no additional SignalR client library required for basic use).
